# Independent workflows: frozen comparison protocol

The existing exact-dependency retention override and V3 dependency sources are
unchanged from `6ebe9ec`; `candidate_freeze.json` checks their hashes. This is a
research candidate, not a production cognition rollout. The task author worked
in a fresh agent context without target code, previous outcomes or Git history.
Their read attestation and immutable task/rubric hashes are in blind_manifest.
This is procedural independence inside one project, not an external benchmark or
an operating-system security barrier.

Six development cases and eight final cases span 14 virtual days and 11 decision
windows. There are 133 independently fixed assertions overall. The final case
contents remain unread by the controller implementer until the code/budgets are
frozen. Six seeds 0–5 per development case establish operational behavior; twenty
seeds 1000–1019 per final case are fixed before final access. Seeds vary noise
within authored structures, not task-family independence. Do not claim 800
independently authored tests from 800 arm executions.

Compare frozen dependency retention, V3 hybrid, FIFO+BM25, task-aware lexical
retention+BM25, and accepted latest-per-key revision heads. All use the native V3
belief/planner machinery and one controller. There is no dense/embedding or live
model result. Lexical retention uses public task labels and conditions; it does
not get evaluator answers. All arms cap complete accessible serialized memory,
controller/plan/reference state and actual query/index material at 16,384 bytes,
16 retained records and four context records/4,096 bytes. BM25 reserves its full
rebuilt Experience/postings/length/df/query representation. Every retrieval,
including admission/belief and discarded planning, is charged before use. This
is a declared logical serialized footprint, not a measurement of Python RSS.
Shared immutable public action schemas and current institutional registers are
external environment inputs for every arm; private truth/assertions are not.

A common gate can prune memory to fit bytes, truncate the ranked context prefix
or withhold a selection whose evidence was evicted. Record all such effects.
No arm receives content through an evicted source ID. Public contracts declare
possible written key names; scripted attempts, statuses and override values are
stripped from controller inputs. Failures block retry of that action pending a
relevant inspection, while unrelated obligations can continue. Inspections
create new direct observations and spend real credits. Unknown private effects
remain hidden. Ledger/economy/clock replay establishes actual consequences.

Primary endpoint: every fixed assertion passes on executed state. Also report
individual assertion failures, unfinished goals, rejections, scripted failures,
partial/unknown receipts, inspection/resource cost, exact receipt counts and
order constraints. No prose intention earns execution credit. Every comparison
world is also run without checkpoints; actual ledger, cash and goal results must
match. No candidate/baseline/controller tuning after the final case access.

Development gate v1 is retained, but its resource measurements are superseded:
independent review found omitted BM25 bookkeeping and uncharged intermediate
retrieval; a selection could outlive its retained support. The source is preserved
as reviewed_harness_v1.py. The common accounting gate was repaired and tested on
synthetic operational fixtures before final access. A recovery deadlock and a
hidden-update/public-register leak were also repaired before final evaluation.
These are correctness fixes to the common harness, not target-score tuning.
Development gate v2 must pass operational/replay checks before the final freeze.

Report final per-case paired completions and cost, not only a pooled headline.
Treat the eight authored cases as the limited generalization unit. Noise seeds
provide within-case robustness, not population confidence. Report ties,
regressions and information limits without adjusting assertions, thresholds or
case weights. Final source/task/rubric hashes are checked before each heldout run;
outputs refuse an existing directory. No paid inference is used.
