# Strategy: make information consequential and inspectable

The strongest implemented technology is an executable chain from private
information to persistent consequences. A seeded city records authoritative
events, local observations, memory answers, evidence-linked decisions, purchases,
commitment settlement, and trust changes. A user can fork its current history,
change an undelivered report or give one citizen a genuine inspection, and
inspect the resulting differences. The local command journal reconstructs both
timelines after restart. This is a working foundation for experimentation;
commercial demand and general scientific superiority remain unproven.

**What could become infrastructure.** The valuable reusable layer is the
boundary between authoritative world transitions and individually scoped
evidence, together with isolated continuations and inspectable state projections.
Existing `Ledger`, `WorldState`, `EpistemicState`, `Experience`, and memory
interfaces already provide much of it. The city adds an economic projection,
message/inspection queues, consequence events, and continuation forks. Those
interfaces could support other settings before a general SDK is justified.
Event sourcing, provenance, memory, and counterfactual simulation are established
techniques; integrating them does not make them new inventions.

**First user experience.** Offer a short, local “fork this conversation's
consequence” investigation: a citizen acts on an outdated grain report; the user
follows its source, changes one delivery or supplies a correction, and watches
both histories continue. The appeal is the ability to explain and change a
consequence through information, rather than only issue commands. A later
training or educational scenario could test whether this interaction helps
people reason about uncertain reports. That potential needs user evidence.

**What would distinguish the product.** The differentiator would be persistent,
editable, inspectable histories whose decisions consume only locally available
information and whose effects are computed. Natural language or visual richness
could make that experience accessible, but neither establishes the underlying
correctness. The present map is schematic, dialogue is absent, and roles do not
yet supply distinct economic strategies.

**What is missing.** The current implementation is a single grain-market model,
one local session with an original and one visible branch, bounded-duration
ticks, and hand-coded behavior. It lacks general scenario authoring, past-tick
rewind/editing, arbitrary action interventions, multi-user hosting, long-running
storage management, and evidence that the experience retains users. Branch
comparisons verify outcomes of chosen edits; the ancestry graph does not prove
that every linked event was necessary. Source roots are honest simulator labels,
without authentication against forged provenance. Memory comparisons disclose
FIFO record budgets, supplied schema/trust fields, and lexical retrieval.
Benchmark regret is a categorical task loss, separate from actual cash and
commitment outcomes. Results and uncertainty belong in the research note.

**Next falsifiable milestone.** Build one independently authored scenario using
the same evidence/decision/fork interfaces, then run five moderated user sessions.
Set a prospective target: at least four users can locate a mistaken belief,
create an intervention, and explain an observed outcome from its trace within
ten minutes without assistance. In parallel, require identity continuations to
match across 100 paired seeds and report every divergence. Failure would identify
whether the next investment belongs in explanation design, engine correctness,
or scenario expressiveness. Adoption would then require repeat use for a real
learning, testing, or entertainment purpose; a platform valuation does not
follow from a successful demonstration.
