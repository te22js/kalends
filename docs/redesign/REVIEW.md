## Main implementation risks

The stable shell already retains life-keyed scene frames and has protocol paths for requests, preview/commit and scene state. Replacing it wholesale risks losing recovery and cross-life guards. Prefer narrow changes with identity/reconciliation tests. The existing frontend also composes guide, history, transaction and character material separately in several places; a copy change in one formatter does not establish that all rendered surfaces changed.

The source register uses local card IDs S2–S5 with a different historical meaning from the old ledger. URLs make the existing mapping recoverable, but bare IDs are unsafe in a combined register. The frozen research all-arm failure is a diagnosis target; no product improvement can turn the existing candidate/V3 tie into a superiority result.

The required scope is larger than visual polish. The final handoff must mark an untested path, missing recording, unresolved high-severity defect or human gate as such, even when automated tests pass. A fresh agent probe must receive exclusive browser control and follow displayed instructions rather than the implementation's scripted solution.
