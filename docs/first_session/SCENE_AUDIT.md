# Pompeii scene: source to screen audit

This is the 3D implementation inventory for the 24 October 2026 first-session repair. It covers PlayCanvas and its HTML interface. The integration owner records actual browser captures, interactions, historical source checks and the final release decision in the release handoff. The automated checks below do not establish human comprehension, enjoyment, educational efficacy, physical-phone operation or assistive-technology compatibility.

## Baseline and preserved behavior

The scene still uses PlayCanvas 2.23.3 and the existing district, character assets, navigation controller, `KalendsBridge` and saved-life HTTP routes. It accepts position intents and server-issued proposal identifiers. Neither guide messages nor rendered frames issue a payment, allocation, promise or tutorial reward. `kalends_3d/dist` is ignored build output, not a tracked deliverable.

The participant source chain is `ExperienceRuntime` / `ExperienceGameFacade` → public game response → `bridge.js` explicit projection → `main.js` HTML and `renderer.js` actor presentation. The guide source chain is the product service's per-life, versioned guide → authenticated parent `kalends:guide` message → `scene_guide.js` bounded presentation → compact objective. Guide acknowledgements go to the parent as metadata requests. They never enter NPC speech, beliefs or memory.

## Reproduced defects and verification

1. **Static-looking population.** The baseline scene defaults `live:false`, so merely reading does not advance the scheduler. The existing Rebirth opening places Sabina and Dama on the street. An isolated `RebirthWorld(seed=2718)` public snapshot run at minutes 0, 12, 30, 45 and 90 established that the inherited minute-12 Dama-to-street task is a no-op. Actual duty moves occur at minute 45 (Sabina to the thermopolium; Dama to the household), then minute 90 (Dama to the bakery). Their public snapshot contains path, movement event and movement minute. Stationary work is deliberate, and the renderer already supports `work` animation from public activity. The repair makes activity legible and explains time. It adds no scheduler, random wandering or new economic behavior. Browser demonstration should deliberately cross minute 45 and capture the rendered routes.

2. **Unseen people can be tracked from the scene journal.** Baseline `renderJournal()` joined every agent to its current location and emitted `Find` buttons; `approach()` routed directly to the latest agent coordinates. The repaired journal hides unseen whereabouts. The guide routes only to a static public place or admitted dated point; a person target needs both displayed and server proximity. Automated cases test an unseen Dama whose newest coordinates differ from the dated street point.

3. **An owner-held document can be read before it is copied.** Fresh `world.context('Sabina')` returned the full `market_receipt` topic and original private evidence ID before `examine_receipt`. Baseline topic clicks directly displayed this text. The scene now admits document topics only when the player's public documents include the matching ID. Withheld report topics go through a reviewed ordinary conversation action. The integration owner repairs the HTTP context projection too; a client filter alone is insufficient to protect network responses.

4. **Dialogue framing can follow a departing person.** Baseline camera target was recomputed from both actor positions each frame, and zoom/rotation remained available during dialogue. The repaired conversation holds its initial focus and ignores camera adjustment while speaking. If a new accepted snapshot moves the speaker for a duty, it closes the conversation and explains the departure. Existing cross-floor and rendered-arrival tests remain enforced.

5. **Time buttons immediately commit a jump.** Baseline `Wait 30m` and `A day later` called the bridge directly. They now open an explicit review with known crossings and a second deliberate advance action. Reading or cancelling the review changes no world minute.

6. **Reading, controls and small text are hard to follow.** Baseline objective body was 11 px; choice notes, topics and status text were as small as 9 px. The repair enlarges the ordinary reading baseline, adds local text-size preferences, a visible canvas focus indicator, wrapping layouts and clearer control verbs. Real viewport checks remain necessary for pixel layout.

## Historical model boundary

The existing scene builder represents `thermopolium_details` with a counter and five inset jar mouths, and `fullery_details` with three water-filled basins (`scripts/build_immersion_scene.py`, thermopolium/fullery room-detail branches). These are schematic furnishings on the room edge, not surveyed archaeological geometry. They support pointing out represented features; they do not establish the particular shop's daily stock or historical worker identities. The existing map labels identify attested building anchors but disclaim reconstructed geography. `SABINA` signage is fictional gameplay, not an ancient inscription. No new source image, generated Latin inscription or image-rights claim was added in this scene work. The root historical ledger governs source claims and qualifications.
