## Implementation order and ownership

1. **Root — lifecycle/backend:** new product service and route wrapper over
   ExperienceService/Runtime, unique life creation, metadata/seen checkpoints,
   compatible per-life loads, safe public projections, known-deadline controls,
   read-only examples, local opt-in telemetry and typed Commons intentions.
   Existing source simulations and frozen experiments stay separate.
2. **Product agent — participant frontend:** only `static/product/` and its
   focused controller tests. Homepage, two actual templates, world details,
   saved lives, stable scene shell, people, history/reflection, explicit LAB,
   research/about/data pages and finite Studio after the core path works.
3. **Reviewer — history and scene continuity:** `history.py` with authorized
   evidence/then-known prefix replay, then a small optional 3D host adapter and
   minimal existing-client glue. No new renderer or transport. Review the
   shared interfaces and privacy boundaries independently.
4. **Research agent — diagnostic and experiment:** instrument the shipped plan
   path, repair a common multi-step controller for all arms when needed, prove
   memory headroom on development cases, then freeze and run one minimal
   retention candidate with full state/context budgets and structural holdout.

Product development runs on port 8810 with `.kalends/next_phase/`; original
journals are never opened for mutation. Baseline and research runs have separate
directories. CPU-heavy research and browser performance measurements are serial.

## Acceptance gates

- **Continuity:** unique identity and exact restart; history preserves the scene,
  camera, recipient/draft and accepted resource state; late responses cannot
  cross lives; failed saves preserve the preceding life.
- **Participant journey:** homepage → supported world → fresh life → ordinary
  interaction → real choice → actual consequence → history → supported alternative
  → return. A declined choice has a coherent continuation. Narrow layout works.
- **Privacy/history:** factual clauses cite admitted events; then-known evidence
  precedes the choice; no narrator installs archive facts into NPC memory;
  operator exposure persists; private events cannot cause unexplained pacing stops.
- **Research:** demonstrate actual memory headroom, negative controls and plan
  reads before claiming a candidate improvement. Shared controller and institutional
  access; charge all retained/working/index/plan state. Freeze primary endpoint,
  variants, budgets and seeds before test execution. Report ties/regressions.
- **Release:** relevant tests, real HTTP/3D integration, complete browser journeys,
  measured responsiveness/frame pacing with conditions, save fingerprint comparison,
  source/results manifests, commits and concise handoff. No human outcomes invented.

## Review and constraints

The independent review confirmed that the remount defect is the mode-return
handler, not every parent refresh. It also identified startup-wide failure on one
bad journal, unrecorded LAB exposure and private aggregate counters unsuitable for
participant copy. The plan therefore adds a thin life-scoped product layer and
public projection rather than rewriting core worlds or simply restyling receipts.

The shipped V3 plan is populated after action choice. The research controller
must actually read common persistent plan state; an old descriptive-plan tie is
the diagnostic starting point, not an excuse to announce a new architecture.
Modern dense retrieval is included only if a pinned approved encoder is actually
available. Current endpoint authorization and budget are absent; live quality is
untested. Human-use protocols/instrumentation can be prepared, not populated with
fabricated volunteers or commercial traction.
